# ADR 0001: Vendor libdave, mlspp, and BoringSSL via SwiftPM C/C++ Targets

## Status

Accepted

## Context

Discord's DAVE (Discord Audio/Video End-to-End Encryption) protocol is required for voice connections as of March 2026. The official reference implementation is `libdave` (C++17), which depends on Cisco's `mlspp` (C++17) and an SSL crypto backend (BoringSSL or OpenSSL).

To provide a zero-friction Swift library for voice bot authors, users should not need to install system dependencies via `brew`, `apt`, `vcpkg`, or CMake. The package should compile completely from source using standard SwiftPM commands (`swift build`, `swift test`).

Crucially, multiple packages in the Swift server ecosystem vendor BoringSSL:
- `apple/swift-crypto` vendored BoringSSL (prefixed with `CCryptoBoringSSL`)
- `apple/swift-nio-ssl` vendored BoringSSL (prefixed with `CNIOBoringSSL`)
- System OpenSSL / LibreSSL may exist in process space on Linux or macOS.

If swift-dave vendored BoringSSL with unprefixed C symbols, linking swift-dave alongside `swift-crypto` or `swift-nio-ssl` would lead to duplicate symbol linker failures or runtime symbol collision crashes.

## Decision

1. **Vendor via SwiftPM Targets**:
   - `CBoringSSL`: Clang target compiling BoringSSL with symbol prefixing (`CCryptoBoringSSL_`).
   - `CMLSPP`: C++17 Clang target compiling Cisco's `mlspp` and `nlohmann/json` with `WITH_BORINGSSL` and `DISABLE_GREASE`.
   - `CLibDave`: C++17 Clang target compiling Discord's `libdave` C API (`dave.h`).
   - `Dave`: Pure Swift library target wrapping `CLibDave`.

2. **Symbol Prefixing & Deconfliction**:
   - `CBoringSSL` uses the prefix symbol renames generated by `swift-crypto`'s toolchain.
   - To prevent preprocessor collision with `mlspp`'s C++ enum values and classes (`Digest::ID::SHA256`, `class HKDF`, `Group::ID::X25519`), the `openssl/*.h` shims undefine those 5 conflicting macros for C++ consumers.
   - Only `dave.h` is exposed in `CLibDave`'s public include directory; internal C++ headers remain private to `src/dave/`.

3. **Validation**:
   - `BoringSSLLinkTests`: Confirms prefixed `CCryptoBoringSSL_SHA256` computes the known test vector for `"abc"`.
   - `LibdaveSmokeTests`: Confirms `daveMaxSupportedProtocolVersion() > 0`, and repeated session/encryptor/decryptor create/destroy runs clean under AddressSanitizer.
   - `Examples/ConflictCheck`: An isolated SwiftPM executable package that links `swift-crypto` + `swift-nio-ssl` + `swift-dave` in the same binary. All three execute without conflict.
   - `scripts/check-symbols.bash`: Verifies that `nm` finds zero unprefixed BoringSSL C symbols in object files.

## Consequences

- **Pros**:
  - Fully self-contained pure SwiftPM build. No CMake or vcpkg needed.
  - Zero collision with `swift-crypto` and `swift-nio-ssl`.
  - Fast incremental build times.
- **Cons**:
  - Vendoring native code increases repository size.
  - Upstream updates must be synchronized through `scripts/vendor.bash` and documented in `Vendor/VERSIONS.md`.
